# HYP-116J. 완성봉 추세 V2 LIVE SHADOW 사전등록

- 상태. `PREREGISTERED_BEFORE_LIVE_SHADOW_RUN`.
- 등록일. 2026-08-30.
- 실행범위. 공개시장 `LIVE_PUBLIC` 입력과 내부 PAPER BASE·STRESS 계좌만 사용한다.
- 수익성 상태. `NOT_PROVEN`.
- 실제 주문 준비. `NOT_READY`.

## 연구 질문

15분·30분 완성봉에서 확인한 추세 눌림 회복 또는 돌파 재확인이 현재 공개 호가·체결 흐름과 함께 나타날 때, 실제 bid·ask, 수수료와 슬리피지 뒤에도 독립적인 양의 순기대값이 남는가?

## 고정 후보

| strategy_id | 신호주기 | 핵심 진입구조 | TP1·TP2 | 안전 백스톱 |
|---|---:|---|---|---:|
| `TREND_PULLBACK_RECLAIM_15M_V2` | 완성 15분 | EMA20 눌림 뒤 이전 고저 회복 | 1.4R·2.8R | 시간청산 없음 |
| `BREAKOUT_RETEST_15M_V2` | 완성 15분 | 32봉 돌파 다음 봉의 지지·저항 재확인 | 1.6R·3.2R | 시간청산 없음 |
| `BREAKOUT_RETEST_30M_V2` | 완성 30분 | 24봉 돌파 다음 봉의 지지·저항 재확인 | 1.6R·3.2R | 시간청산 없음 |
| `MULTISPEED_TREND_RECLAIM_30M_V2` | 완성 30분 | 30분 EMA20 조정 뒤 1시간 방향 재합류 | 1.5R·3.0R | 시간청산 없음 |

네 전략은 LONG·SHORT를 대칭으로 평가한다. TP1은 40%, TP2는 60%를 청산한다. 최초 손절은 최근 재확인 또는 눌림 구조 밖에 두고 진입 뒤 넓히지 않는다.

## 공통 사전조건

- 신호주기 완성봉 100개와 완성 1시간봉 50개 이상이 연속이어야 한다.
- 15분·30분 EMA20·EMA80와 1시간 EMA20·EMA50가 진입 방향으로 정렬되어야 한다.
- 전략별 24시간 모멘텀 1.0~1.5%, ADX 18~20, 상대거래량 0.8~1.1배 gate를 고정한다.
- 새 완성봉 뒤 5초 이내 sequence-valid 공개시장 입력만 사용한다.
- spread는 12bp 이하여야 하고 OFI 1초·3초, 3초 aggressor 체결 불균형과 microprice가 방향에 정렬된 상태가 1초 이어져야 한다.
- 구조 손절 거리는 0.65~3.0 ATR이고 최종 실제 호가 계획의 비용후 순손익비는 1.20 이상이어야 한다.
- LONG 진입은 실제 ask, SHORT 진입은 실제 bid를 사용하고 청산은 반대쪽 실행가능 호가를 사용한다.

## 청산 계약

- 일반 미시구조 `EDGE_DECAY`는 네 전략에 적용하지 않는다.
- 구조 손절, TP1, TP2, 손절의 이익보호 방향 단축, 데이터·시스템 안전종료는 계속 적용한다.
- 경과시간만으로 청산하지 않는다. TP1·TP2·구조 손절과 이익보호 방향의 손절 단축으로 결판내며, 데이터·시스템 안전종료는 전략 판단과 분리한다.
- 기간 끝에 미완료인 연구 거래를 성공이나 실패로 임의 분류하지 않는다. 원장 상태와 censored 여부를 보존한다.

## V1 중복 방지

이 후보들은 이전 `HOURLY_MOMENTUM_BREAKOUT_V1` 또는 기존 intraday 연구의 단순 파라미터 변경이 아니다. V1의 직접 돌파 추격을 사용하지 않고, 돌파 다음 완성봉 재확인 또는 EMA20 눌림 뒤 이전 고저 회복과 신호 이후 현재 공개 주문흐름을 새 필수조건으로 둔다. 이전 V1 실패 표본은 새 V2 성과에 섞지 않는다.

## 비용과 계좌

- 각 전략은 BASE와 STRESS 1,000 USDT 독립 PAPER 계좌를 가진다.
- 포지션당 계획위험은 독립계좌 자산의 0.5%를 넘지 않는다.
- BASE는 기존 왕복 비용·250ms 체결지연, STRESS는 더 높은 비용·500ms 지연과 2배 slippage를 사용한다.
- 실제 주문, private API, API Key, 인증, secret, wallet, 입출금 기능은 0이다.

## 반증과 승격 금지선

다음 중 하나라도 충족하면 수익성을 입증하지 못한다.

- 현재 버전의 자연 `LIVE_PUBLIC` 고유 기회가 비용 프로필별 30건 미만이다.
- BASE 또는 STRESS 순기대값이 0 이하이거나 Profit Factor가 기준을 통과하지 못한다.
- bootstrap 기대값 하한이 0 이하, DSR이 0.95 미만 또는 PBO가 0.20 초과다.
- 특정 종목·방향·레짐·시간대에 성과가 과도하게 집중된다.
- 시간순 OOS, BASE·STRESS, drawdown 또는 payoff gate가 실패한다.
- LIVE 처리지연, queue, gap, drop, 저장결함을 늘려 PAPER 안전을 훼손한다.

30건 전에는 순위를 매기지 않는다. 30건은 수익성 확정점이 아니라 첫 평가 최저선이다. `SHADOW→CHALLENGER`와 `ACTIVE` 전환은 기존 Governor의 더 긴 7일·21일, 레짐, 표본, 강건성 gate를 모두 따른다.

## 출처와 해석 경계

- Moskowitz, Ooi, Pedersen의 Time Series Momentum은 전통 선물의 월 단위 추세 가설 출처다.
- Rozario 등의 암호화폐 추세 연구는 과거 walk-forward 가설 출처다.
- 두 자료 모두 15분·30분 Binance USDⓈ-M PAPER 수익성 증거가 아니다.
- Binance 공개 kline, depth와 aggregate trade 문서는 필드와 sequence 계약에만 사용한다.
- 코드나 실제 주문 경로를 외부 프로젝트에서 가져오지 않았다.

## 변경 금지

이 사전등록 이후 관찰 중 거래 수나 승률을 높이기 위해 threshold, 비용, spread, 확인시간, 구조 손절, TP, 슬리피지 또는 표본 gate를 낮추지 않는다. 결함 수정은 재현 테스트와 새 strategy version으로 분리하고, 이전 거래와 판단 근거는 삭제하지 않는다.
