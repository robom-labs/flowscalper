# ADR-138. 구조 근거 TP1·TP2와 TP1 이후 runner

- 상태. 채택.
- 일자. 2026-09-02.
- 범위. 현재 `SHADOW` 실행 전략 6개의 새 PAPER 진입만 해당한다.
- 수익성 상태. `NOT_PROVEN`.

## 배경

기존 진입 손절은 가격 구조를 쓰지만 TP1·TP2는 전략 descriptor의 고정 R 배수에
주로 의존했다. 이 방식은 손익비 필터에는 유용하지만, 왜 해당 가격이 실제 차트의
저항·지지·평균회귀 목표인지를 설명하지 못한다. 또한 TP1 후 남은 수량을 무조건
TP2까지 유지하면 이미 확보한 수익을 되돌릴 수 있다.

## 결정

1. 모든 새 진입은 실제 반대호가, 초기 손절, TP1, TP2, 수량, 최대계획손실,
   BASE·STRESS 비용과 TP1 후 관리방식을 진입 전에 한 계획으로 고정한다.
2. `CBR_CONTINUATION_V1`은 최근 10초 실거래 경로의 출발→눌림→재가속을 사용한다.
   손절은 실제 눌림 극값 바깥, TP1은 이전 충격 극값, TP2는 확인된 첫 충격폭의
   측정 목표다. TP1에서 40%를 정리한 뒤 남은 60%는 실제 눌림폭으로 추적한다.
3. `VWAP_EXHAUSTION_REVERSION_V1`은 최근 2분 실거래 이탈 극값 바깥을 손절로 두고,
   TP1을 과도이탈 전 실제 가격대 중앙, TP2를 그 가격대의 반대편 미세 피벗 또는
   실제 이탈폭의 대칭 범위로 고정한다. 10초 micro-VWAP은 목표가가 아니라 구조 재진입
   확인에만 쓰며 TP1에서 70%, TP2에서 30%를 정리한다.
4. `TREND_PULLBACK_RECLAIM_15M_V2`, `BREAKOUT_RETEST_15M_V2`,
   `BREAKOUT_RETEST_30M_V2`, `MULTISPEED_TREND_RECLAIM_30M_V2`는 진행 중 봉을 배제한다.
   해당 15·30분 완성봉, 1시간 완성봉, 이전 UTC 일중 고저, 확정 피벗, 돌파 측정폭,
   완성봉 ATR 채널 중 진입 방향의 가장 가까운 유효 가격을 TP1로, 다음 구조 가격을
   TP2로 선택한다.
5. 중단기 추세 4개는 TP1에서 40%를 정리하고 남은 60%를 해당 15·30분 완성봉
   ATR Chandelier로 추적한다. 추적선은 이익 보호 방향으로만 움직이며 손절을 넓히지 않는다.
6. 목표 가격이 실제 호가 왕복비용 밖에 있지 않거나 최종 비용후 순손익비 1.20을
   넘지 못하면 임의의 R 배수로 TP를 늘리지 않고 진입을 거부한다.
7. 해당 근거 문장과 확인 시간구간을 후보 원장, 재시작 복구 snapshot, 현재 포지션,
   거래 다시보기에 동일하게 보존한다. 이전 버전 거래에 없는 근거는 새로 지어내지 않는다.
8. 이 변경은 새 진입에만 적용한다. 이미 열린 PAPER 포지션은 진입 당시 불변 계획을
   그대로 유지한다.

## 노룩어헤드 방지

- 피벗은 두 개의 후속 완성봉으로 이미 확인된 가격만 쓴다.
- 완성봉 참조 시각이 신호 시각보다 느리거나 봉 시각이 중복·불연속이면 계획을 만들지 않는다.
- 진입 체결 직전 실제 호가가 이미 TP1을 지났거나 절대 가격 순서가 무너지면 계획을 재가공하지
  않고 진입을 거부한다.

## 기각한 대안

- 모든 전략에 같은 1.5R·3.0R를 계속 사용하는 안은 전략별 차트 근거를 설명하지 못해 기각한다.
- TP1에 도달하기 전에 수익 추적선을 활성화하는 안은 원래 구조 손절을 흐릴 수 있어 기각한다.
- 거래 수를 늘리기 위해 구조·비용·호가·확인 기준을 낮추는 안은 기각한다.

## 근거와 검증 경계

- TradingView의 전략 문서는 진입 전 확정된 부분청산과 trailing stop 주문 모델, pivot의 지지·저항
  해석을 설계 참고로만 사용했다.
- Fidelity의 진입·청산 교육 자료는 가격 목표, stop, trailing stop의 역할을 설계 참고로만 사용했다.
- 이 자료들은 해당 암호화폐 전략의 수익성 증거가 아니다. 실제 bid·ask, 수수료, 슬리피지, BASE·STRESS,
  시간순 OOS와 충분한 미래 `LIVE_PUBLIC` 표본 전에는 수익성을 주장하지 않는다.
