# ADR-109. 병렬 추세 후보 토너먼트와 퇴역 기록 보존

- 상태. 채택.
- 일자. 2026-08-30.
- 범위. 다수 전략 후보를 빠르게 비교하면서도 기존 전략의 거래·근거·회귀증거를 잃지 않는 연구 수명주기에 적용한다.

## 배경

전략을 한두 개씩 순차로 켰다 끄면 같은 시장구간에서 공정하게 비교하기 어렵고 좋은 후보를 찾는 속도도 느리다. 반대로 결과가 약한 전략을 소스와 기록에서 삭제하면 실패 원인, 중복 후보와 과최적화를 추적할 수 없다. 검증 전 후보 수십 개를 LIVE runtime에 바로 등록하면 활성 PAPER 처리와 원장 안전을 훼손하고 작은 우연 표본을 성과로 오해할 위험도 있다.

고정 900초 청산은 전략의 구조가 아직 유효한데 시간만 지났다는 이유로 비용을 확정할 수 있다. 그렇다고 모든 안전종료를 제거하면 데이터 단절이나 원장 결함 때 PAPER 상태가 보호되지 않는다.

## 결정

1. 서로 다른 6계열·24개 추세 후보를 결과 전에 사전등록하고 같은 공개 완성봉, 같은 BASE·STRESS 비용과 같은 시간순 split에서 동시에 평가한다.
2. 후보별 PAPER 경로는 독립적으로 계산한다. 결과에는 통과 후보뿐 아니라 24개 전부의 표본, 승률, 기대값, PF, drawdown, 종료사유와 censored 수를 남긴다.
3. 역사 결과가 약한 후보는 삭제하지 않는다. 코드 버전, candidate fingerprint, 입력 hash와 결과를 보존하고 `REJECTED` 또는 `NOT_PROVEN` 연구기록으로 남긴다.
4. 기존 runtime 전략의 `RETIRED·OFF`도 삭제가 아니다. 전략 소스, 과거 거래, 가상계좌, 판단근거와 회귀테스트가 남아 있으므로 같은 실패를 새 이름으로 반복하는 일을 막는다.
5. 역사 train·validation gate를 통과한 서로 다른 계열 최대 3개만 진단 OOS를 연다. OOS까지 통과해도 자동으로 ACTIVE로 승격하지 않고 실제 공개 bid·ask BASE·STRESS SHADOW 미래표본을 요구한다.
6. 연구 후보를 많이 동시에 평가하는 일과 LIVE runtime에 무제한 등록하는 일을 분리한다. 연구 병렬성은 높이되 활성 공개시장 처리·저장·화면 안정성은 기존 안전상한을 유지한다.
7. 구조형 신규 후보에는 고정 최대보유시간과 900초 전략청산을 두지 않는다. TP1·TP2·구조 손절로 결판내고 연구 종료 시 미결은 `CENSORED_OPEN`으로 보존한다.
8. 데이터·시스템 안전종료는 전략 최대보유와 분리해 유지한다. 최초 손절은 진입 뒤 넓히지 않으며 TP1 뒤 비용보호 방향으로만 줄인다.
9. 사용자 화면의 생존 후보군은 충분한 동일조건 증거가 생긴 뒤 약 10개를 유지한다. 더 나은 후보가 같은 gate를 통과할 때만 가장 약한 후보를 퇴역시키고 기록은 삭제하지 않는다.

## 검증 계약

- 후보 수 24, ID 고유성, 6계열, 15분·30분 각 12개를 테스트한다.
- 같은 봉의 손절 우선, 다음 봉 시가 진입, TP1 뒤 비용보호 손절과 무강제보유 censored를 테스트한다.
- 미래 봉 변경이 과거 신호를 바꾸지 않는지 확인한다.
- 나뉜 공개 cache가 정확히 이어지는지 검증하고 gap은 fail-closed한다.
- 후보와 판정 기준을 커밋한 뒤에만 역사 토너먼트를 실행한다.
- 결과가 좋지 않아도 threshold를 낮추거나 후보를 삭제하지 않는다.
- 실제 주문, private API, API Key, 인증, secret, wallet과 입출금 경로가 계속 0인지 전체 안전검증을 다시 실행한다.

## 경계

24개 동시 연구는 거래 수를 억지로 늘리거나 70% 승률을 보장하는 기능이 아니다. 자연신호가 없으면 조건을 낮추지 않는다. 후보의 높은 역사 승률도 실제 bid·ask 미래표본, BASE·STRESS, 표본 수, 시간순 OOS와 강건성 gate 전에는 `NOT_PROVEN`이다. 실자금 자동매매 준비상태는 계속 `NOT_READY`다.
