# ADR-084. 비용을 넘는 가격 악화 확인과 초보자 우선 결과 화면

## 상태

Accepted, 2026-08-28.

## 문제

배포 전 현재 전략 버전의 실제 공개시장 PAPER 독립계좌 거래 30건을 원장 API로 다시
집계했다. 30건 모두 `EDGE_DECAY`였고 보유시간은 13.622~46.368초였다. 가격 손익 합계는
+1.532780 USDT였지만 수수료와 슬리피지 합계가 33.260573416 USDT여서 순손익은
-31.727793416 USDT였다. 16건은 가격 손익이 양수인데 비용 때문에 순손실이 됐고 8건은
가격이 사실상 평탄한 상태에서 종료됐다. 기존 10초 유예·복수 근거·3초 지속 계약은
1~3초 종료를 막았지만 가격과 비용을 확인하지 않아 비용만 확정하는 반복 종료를 허용했다.

거래기록은 trade ID, Run ID, 전략 코드, 계좌 코드, 원시 종료 코드와 10개 열을 기본 화면에
펼쳤다. 전략·성과·진행거래도 BASE/STRESS, Profit Factor, R/bp와 내부 개정 정보를 기본
표에 노출해 비전문가가 현재 결과와 보호 상태를 파악하기 어려웠다.

## 결정

1. 일반 `EDGE_DECAY` 유예는 체결 뒤 30초로 늘린다. 초기 SL, TP1, TP2, 데이터 안전종료와
   명시적 최대 보유 종료는 영향을 받지 않는다.
2. 유예 뒤 서로 다른 불리한 건강 근거가 최소 2개 동시에 존재해야 한다.
3. LONG은 실행 가능한 best bid, SHORT는 best ask로 현재 R을 계산한다.
4. 이익 보호가 아직 활성화되지 않은 일반 종료는 현재 손실이 `max(0.25R, 계획 왕복비용 R)`
   이상 불리할 때만 3초 지속 확인을 시작한다. 가격이 비용 구간 안으로 회복하면 확인시각을
   초기화한다.
5. MFE +0.8R 이후의 이익 보호는 기존처럼 30초 유예와 가격손실 확인을 생략할 수 있지만,
   복수 불리 근거와 3초 지속은 유지한다.
6. 정책 변경은 전략 구현 개정을 `2026-08-28-wave102`로 올려 과거 거래와 새 자연 표본을
   섞지 않는다. 과거 거래는 삭제하거나 재작성하지 않는다.
7. 거래기록 기본 목록은 거래·전략/계좌·최종 순손익·쉬운 종료 이유·보유시간·다시보기만
   표시한다. 원장 ID와 원시 코드는 접힌 기술 정보에 둔다.
8. 전략·성과·진행거래 화면은 쉬운 한국어 핵심 상태만 펼치고 연구 지표·수량·레버리지·
   원시 모델명은 접힌 고급 정보에 둔다. 작은 화면에서는 행을 카드로 재배치한다.
9. 실제 주문, private API, 인증, API Key와 wallet 경로는 계속 0으로 유지한다.

## 검증

- 30초 전 일반 근거약화가 청산되지 않는지 확인한다.
- 가격이 평탄하거나 가격손실이 왕복비용 R보다 작으면 불리한 근거가 지속돼도 보유하는지
  확인한다.
- 가격손실이 비용 구간을 넘고 복수 근거가 3초 지속될 때만 일반 관리종료가 준비되는지
  확인한다.
- 이익 보호, 초기 TP/SL, stale 안전종료와 불변 stop 계약이 회귀하지 않는지 확인한다.
- 거래기록·전략·성과·진행거래의 기본 표에 원시 ID와 원시 종료 코드가 보이지 않고, 접힌
  상세에서는 감사 정보가 보존되는지 확인한다.
- 데스크톱·태블릿·모바일 실제 브라우저에서 잘림과 가로 흔들림 없이 핵심 조작이 가능한지
  확인한다.

## 한계

이 변경은 수수료만 반복해서 확정하는 종료 결함을 줄이는 안전·비용 정책이다. 승률이나
수익성을 높였다는 증거가 아니다. 새 전략 버전의 실제 공개시장 자연 표본은 다시 0건부터
수집하며 30건·시간순 OOS·BASE/STRESS·강건성 gate 전에는 `NOT_PROVEN`을 유지한다.
