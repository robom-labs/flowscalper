# ADR-107. LIVE 저장 batch 상한과 관찰구간 지연 판정

- 상태. 채택.
- 일자. 2026-08-30.
- 범위. 공개시장 PAPER 원장 저장, macOS 준비 판정과 비침습 실행 관찰에 해당한다.

## 배경

1,000개 시장행을 한 번에 외장 SQLite와 archive에 확정하는 구간에서 flush 28.747초와 WAL checkpoint 37.021초가 관찰됐다. 이후 저장이 회복돼도 관찰기는 프로세스 시작 뒤의 마지막 느린 수치를 모든 새 구간에 반복 귀속했다. 반대로 macOS 설치기는 공개시장 연결과 PAPER 안전만 확인해 시작 직후 처리 p95 679.366ms인 상태에서도 준비 완료를 반환했다.

## 결정

1. LIVE 시장 저장 batch 상한을 1,000개에서 500개로 줄인 뒤, 단일 SQLite FULL 확정 21.219초가 다시 관찰돼 250개로 더 줄인다. 원자성, `synchronous=FULL`, 감사행과 복구 snapshot 계약은 유지한다.
2. 실행 관찰기는 관찰 시작 뒤 해당 작업의 count가 실제로 증가한 경우에만 그 구간의 flush·WAL 마지막 지연을 판정한다. 시작 전에 끝난 과거 느린 작업은 기준선에 보존하되 새 실패로 반복 계산하지 않는다.
3. count가 관찰구간 안에서 전진한 새 느린 작업은 기존 상한인 flush 20초, WAL checkpoint 30초로 계속 실패한다.
4. macOS 설치기는 release 격리, LIVE 공개시장, PAPER, 실제 주문 false, 인증 false, 시장관찰과 자동복구뿐 아니라 처리 p95 500ms 이하, 체결 흐름 p95 1,000ms 이하, 저장 worker 준비, 최소 4회 flush, 최근 flush 20초 이하, 저장결함·buffer drop 0과 저장 진입 허용을 모두 만족한 뒤에만 준비 완료를 출력한다.
5. 이전 FAIL JSON은 삭제하거나 PASS로 덮어쓰지 않는다. 수정 전, 중간, 수정 후 관찰을 별도 파일로 보존한다.

## 실제 관찰

- 수정 전 최종 관찰은 flush 28.747초·WAL 37.021초로 FAIL했다.
- 500개 batch를 처음 적용한 관찰은 저장 상한을 통과했지만 시작 표본 처리 p95 679.366ms 때문에 전체 FAIL이었다. 종료 표본은 23.424ms로 회복했다.
- 준비 판정 보강 뒤 120.017초 관찰은 event +7,923, 전략평가 +51,880, 처리·체결 p95 최대 36.839·75.606ms, queue 최대 0, flush·WAL 최대 1.680·1.440초로 PASS했다.
- TP·SL 결판 릴리스의 다음 90.017초 관찰은 event +5,593, 전략평가 +39,420, 처리·체결 p95 최대 26.062·41.301ms와 재연결·gap·drop·저장결함 0이었지만, 500개 시장 이벤트와 81개 캔들의 단일 SQLite FULL 확정이 21.219초 걸려 flush 상한을 1.719초 넘겼다. 전체 결과는 `FAIL`로 보존한다.
- 이 실패의 Parquet archive 구간은 0.477초였으므로 저장 원자성과 `synchronous=FULL`을 낮추지 않고 batch 상한을 250개로 줄였다. 최종 설치와 실행 관찰 결과는 별도 증거에 기록한다.
- 같은 구간의 비계획 재연결, gap, resync, drop, 저장결함, buffer drop, 실제 주문과 인증은 0이었다.

## 검증 경계

120초 PASS는 시작 준비와 단기 저장 안정성 증거다. 6시간·24시간은 실제 경과 전까지 `NOT_RUN`이며, 자연 적격신호가 0이므로 진입·TP·SL의 새 공개시장 수명주기는 `NOT_OBSERVED`, 수익성은 `NOT_PROVEN`이다.
