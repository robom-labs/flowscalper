# ADR-068 LIVE 거래 집중 재생의 비차단 조회와 비용 단계 표시

- 상태는 승인이다.
- 날짜는 2026-08-27이다.
- 후속 읽기 성능 경로는 ADR-069가 대체하며, 이 ADR의 비용 배분과 cache schema 7 결정은 유지한다.

## 맥락

commit `50d97075fc99fe79d9c426506d59521582eeccc6` 실제 8870 화면에서 미캐시 거래 집중 재생을
두 번 열었다. 공개시장 event와 PAPER 관리는 계속 전진했지만 첫 BNBUSDT 화면은 약 29초,
두 번째 DOGEUSDT 화면은 36초를 넘겨 준비 상태가 이어졌다. 같은 거래의 캐시 적중 요청은
0.540초였고, 동일 원장을 직접 읽어 캐시 쓰기만 생략한 builder는 0.077초였다. LIVE 영속화
프로세스가 최대 60초 `busy_timeout`으로 `BEGIN IMMEDIATE`를 사용하는 동안 선택적 focus cache
쓰기가 기다리는 경로가 사용자 대기의 원인이었다.

완료 거래의 원장에는 총 수수료와 총 슬리피지가 보존되지만 과거 shadow 거래에는 진입·종료
수수료가 별도 필드로 남지 않는다. 기존 화면은 총 수수료를 전부 `진입 수수료`로 표시하고
`종료 수수료`를 0으로 표시해, 비용 합계는 맞지만 단계별 문구가 틀렸다.

## 결정

LIVE process-isolated focus builder는 기존 cache를 읽을 수 있지만 새 cache를 쓰지 않는다. 대상
거래·후보·같은 전략 비교·시간창 조회는 그대로 제한하고, 계산 결과를 바로 API에 반환한다.
DEMO와 직접 runtime 경로는 기존 결정적 압축 cache를 유지한다. 이는 장기 공개시장 영속화의
우선순위와 같은 Run 원장을 바꾸지 않는 읽기 전용 UI 경계다.

과거 완료 거래의 총 수수료는 실제 진입·종료 명목금액 비율로 나눠 두 합계가 원장 총액과 정확히
일치하게 한다. 총 슬리피지는 후보의 계획 진입 대비 실제 진입의 불리한 차이를 먼저 진입분으로
배정하고 나머지를 종료분으로 둔다. 재생 진입 중에는 진입 수수료와 예상 종료비를 구분하고,
종료 프레임에서는 진입 수수료와 실현 종료 수수료를 구분한다. 캐시 schema는 7로 올려 과거의
잘못된 비용 분류 화면을 재사용하지 않는다.

## 결과

focus 화면은 LIVE SQLite 쓰기 잠금을 기다리지 않고 읽기 결과를 반환하며, 재생 단계별 비용
문구와 원장 총비용 합계가 일치한다. 전략 임계값, 진입·TP·SL·청산정책, 비용률, 계좌, 위험예산은
바뀌지 않는다. 실제 주문·private API·인증·API key·secret·wallet 경로는 계속 0이다.
