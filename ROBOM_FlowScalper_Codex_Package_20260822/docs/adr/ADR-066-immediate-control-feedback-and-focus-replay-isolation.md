# ADR-066 즉시 제어 피드백과 거래 집중 재생 격리

- 상태는 승인이다.
- 날짜는 2026-08-27이다.

## 맥락

실제 설치 화면에서 `새 진입 잠시 멈춤`과 `새 진입 다시 시작`은 서버가 변경된 dashboard를
반환할 때까지 버튼 문구가 그대로여서 사용자가 클릭 수신 여부를 알 수 없었다. 같은 Run을
유지한 실제 재개는 정상 완료됐지만 화면 반영까지 약 5초가 걸렸다.

현재 Run의 실제 거래 집중 재생은 거래 원장 전체와 shadow 원장 전체를 읽은 뒤 한 거래를
찾고, LIVE 프로세스 안의 thread에서 focus 세션을 만들었다. 3GB 활성 원장 유지관리와 로컬
회귀검사가 겹친 실제 관찰에서는 8프레임 거래가 화면에 나타나기까지 약 3분이 걸렸다. 이
관찰은 다른 I/O와 브라우저 조작이 겹쳤으므로 단독 성능 기준은 아니지만, 광범위 원장 읽기와
LIVE 프로세스 공유 경계를 제거할 근거로 충분하다.

## 결정

pause·resume 요청을 보내기 직전에 클라이언트의 즉시 작업 상태를 설정한다. 서버 응답 또는
오류가 올 때까지 해당 버튼을 비활성화하고 `잠시 멈추는 중…` 또는 `다시 시작하는 중…`을
표시한다. 서버의 revision, idempotency key, 사용자 의도와 자동 안전잠금 계약은 그대로 둔다.

LIVE 거래 집중 재생은 저장 Run timeline과 같은 별도 process lock과 process worker를 사용한다.
원장은 `(run_id, trade_id, profile)`로 대상 거래 한 건을 조회하고, BASE·STRESS 비교도 같은
Run·전략·종목·방향의 행만 제한해 읽는다. shadow 거래 checksum 검증과 미래 이벤트 비노출,
프레임 checksum, 실제 bid·ask PAPER 체결 계약은 유지한다.

## 결과

클릭이 접수됐는지 즉시 보이며 중복 클릭을 막는다. 집중 재생의 CPU·SQLite 읽기는 LIVE event
loop와 분리되고 전체 거래표 역직렬화를 피한다. 실제 설치 릴리스의 지연 개선은 새 불변 배포
뒤 다른 회귀나 유지관리 작업을 겹치지 않은 브라우저 측정으로 별도 증명한다.

전략 임계값, 비용, TP, SL, 체결, Governor, 위험예산과 계좌 구성은 바꾸지 않는다. 실제 주문,
private API, API key, secret, wallet과 런타임 AI 주문판단은 계속 0이다.
