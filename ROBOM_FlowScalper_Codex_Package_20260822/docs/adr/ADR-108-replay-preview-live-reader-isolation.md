# ADR-108. 과거 재생 목록과 LIVE 원장 읽기 격리

- 상태. 채택.
- 일자. 2026-08-30.
- 범위. 과거 재생 첫 화면, Run·종목·최근 캔들 조회와 활성 PAPER 원장 동시 접근에 해당한다.

## 배경

활성 Run의 `/api/replay/runs`는 0.012초 이내에 응답했지만, 첫 Run의 500개 캔들 미리보기는 실제로 약 29.399초가 걸렸다. 화면은 Run 목록과 현재 작업을 받은 뒤에도 첫 미리보기를 `await`해 전체 `loading`을 해제했기 때문에 사용자는 저장 기록 선택기 대신 `저장 기록 목록을 확인하는 중입니다`만 보았다.

원장 조사 결과 미리보기 자체가 대형 이벤트 본문을 스캔한 것은 아니었다. Run 존재 확인, 종목 통계와 최근 캔들 세 조회가 모두 활성 SQLite 쓰기 연결의 같은 잠금을 사용해, 공개시장 batch의 FULL 확정이 끝날 때까지 기다린 것이 직접 원인이었다.

## 결정

1. `get_run`, `market_event_symbols`, `list_recent_candles`는 일반 화면·시작 캐시와 공유하지 않는 replay 전용 WAL query-only 연결과 잠금을 사용한다. 공개시장 쓰기 트랜잭션, `synchronous=FULL`, 원자성, checksum과 불변 원장은 바꾸지 않는다.
2. 과거 재생의 Run 목록 로딩과 첫 캔들 미리보기 로딩을 서로 다른 화면 상태로 분리한다. Run 목록이 도착하면 선택기를 즉시 활성화하고, 캔들은 `저장된 최근 캔들을 불러오는 중입니다`로 별도 표시한다.
3. 미리보기 중 다른 Run을 선택할 수 있으므로 요청 순번을 기록하고 가장 최근 요청만 화면 상태를 바꾸게 한다. 늦게 끝난 과거 요청은 새 Run·종목을 덮지 않는다.
4. 정밀 이벤트와 같은 조건 전략 검증은 계속 사용자의 명시적 버튼으로만 실행한다. 목록·캔들 미리보기가 전체 이벤트 replay를 자동 실행하지 않는다.
5. 실제 주문, private API, API Key, 인증, wallet과 실제 자금 경로는 계속 0으로 유지한다.
6. 화면용 정밀 이벤트는 archive manifest의 최신 시장시각 순서에서 선택 종목을 포함하는 batch만 역순으로 제한해 checksum을 검증하고, 최근 100건을 수신 순서로 표시한다. 전체 전략 검증은 저장 입력 전체를 계속 사용하므로 화면 최적화가 연구 범위를 줄이지 않는다.

## 검증 계약

- LIVE 쓰기 잠금과 일반 읽기 잠금을 동시에 인위적으로 점유한 동안에도 저장 Run 미리보기가 1초 이내에 끝나는 backend 회귀 테스트를 둔다.
- 첫 캔들 응답을 의도적으로 지연한 동안 Run 선택기가 활성화되고 목록 로딩 문구가 사라지는 frontend 회귀 테스트를 둔다.
- 여러 archive batch 중 최신 window에 필요한 batch만 읽고 정확한 최근 이벤트를 시간순으로 반환하는 backend 회귀 테스트를 둔다.
- 활성 대형 Run에서 설치 전·후 API 응답 시간을 다시 측정하고 실제 브라우저에서 목록, 미리보기, 종목 선택과 거래 집중 재생을 확인한다.

## 경계

목록과 미리보기 개선은 과거 데이터 가시성과 LIVE 처리 격리의 증거다. 전략 수익성, 70% 승률, 자연 진입이나 6시간·24시간 안정성을 증명하지 않는다. 자연표본과 강건성 gate가 부족한 전략은 계속 `NOT_PROVEN`이며 실자금 전환은 `NOT_READY`다.
