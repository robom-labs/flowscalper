# ADR-015. 장시간 처리량 안정화와 차트 전체화면 대체 동작

## 상태

Accepted, 2026-08-25.

## 문제

약 10시간 실행된 공개시장 PAPER Run `run-07ad829dbe61`에서 실행 경로 처리지연 P95가 5,318~7,875ms까지 올라갔다. queue·drop·저장 fault는 없었지만 단일 Python 처리 경로가 CPU를 계속 사용했고 PAPER 신규진입은 지연 안전정책에 따라 잠겼다.

실제 서비스 프로파일에서 전체 1,000단계 호가 중 상위 가격이 삭제될 때의 전체 정렬과, 종목별 1,200개 과거 표본이 찬 뒤 매 전략평가마다 통계 입력을 다시 만들고 정렬하는 경로가 실행시간에 따라 반복 비용을 키웠다. 별도로 일부 모바일·앱 내 브라우저는 native Fullscreen API 요청을 완료하지 않아 차트 전체화면 버튼이 반응하지 않았고, 모바일 가격 통계 레이어가 버튼 클릭영역을 가로막을 수 있었다.

## 결정

1. 각 로컬 주문장은 bid·ask의 전체 가격 인덱스를 오름차순으로 유지하고 delta마다 `bisect`로 정확히 삽입·삭제한다. 상위 20단계와 20단계 초과 조회는 같은 인덱스에서 파생한다.
2. 호가 수량과 Decimal 가격은 기존 dict 원장을 계속 기준으로 삼으며 sequence, crossed-book, gap fail-closed 계약은 변경하지 않는다.
3. 전략평가기는 종목별 기존 1,200개 `FeatureSnapshot` 창과 함께 통계 입력 6종의 정렬 창을 유지한다. 오래된 snapshot 퇴출과 새 snapshot 삽입을 동일 순서로 수행한다.
4. robust z와 percentile은 기존 정의와 정확히 같은 값을 내는 정렬 입력 전용 함수를 사용한다. 전략 임계값, history 길이, 확인시간과 비용 기준은 변경하지 않는다.
5. 차트 전체화면은 클릭 즉시 앱 CSS 전체화면 상태를 켠 뒤 native Fullscreen API를 시도한다. native API가 없거나 거부돼도 CSS 전체화면을 유지한다.
6. 모바일 compact 차트의 `지표`와 `전체화면`은 한 줄에 유지하고 비대화된 통계 표시 레이어는 포인터 입력을 받지 않는다.

## 검증

- 정렬 통계 함수와 기존 기준 함수의 빈 창, 동률, 홀수·짝수, 음수 표본 결과가 정확히 같은지 검사한다.
- 3개 제한창에서 snapshot 퇴출 뒤 원본 deque와 6개 정렬 입력이 정확히 일치하는지 검사한다.
- 무작위 500회 호가 add·update·remove 뒤 상위 20단계와 전체 정렬 기준을 대조하고 50단계 조회도 검사한다.
- 가득 찬 1,200표본·20종목 평가와 1,000단계 top 삭제·재삽입 microbenchmark를 변경 전후 동일 입력으로 비교한다.
- 실제 8870에서 시작·일시정지·재개, 자연 PAPER 체결·TP/SL, 기록·분석·재생과 전체화면 열기·닫기를 직접 확인한다.
- 데스크톱·태블릿·모바일 Playwright에서 전체화면 CSS 상태와 버튼 복귀, chart 크기 안정, console/page error 0을 검사한다.

## 한계

이번 변경 뒤 실제 연속 관찰은 약 20분과 별도 1분 표본이며 6시간·24시간 soak가 아니다. 1,200표본 포화 경로는 결정론적 microbenchmark와 테스트로 검증했지만 멀티시간 실행 완료로 표현하지 않는다. 전략 수익성도 증명하지 않는다.
