# ADR-098. 증거 통과 전략 생존 감시목록

## 상태

채택한다. 전략 연구는 전체 후보를 지우고 다시 시작하지 않는다. 각 가설·파라미터·버전·Run의 거래와
판단 근거를 계속 누적하고, 사전에 고정한 공통 시장입력에서 비용·강건성 관문을 통과한 후보만 최대 10개
생존 감시목록에 둔다.

## 문제

목표 승률을 빨리 얻기 위해 전략 수를 무조건 늘리거나 낮은 승률 전략을 즉시 삭제하면 다중시험, 표본 생존 편향,
선택 편향이 커진다. 30건 미만의 80%와 비용 후 손실인 70%를 생존 전략으로 보면 실전 가능성이 아니라 작은
표본의 우연을 관리하게 된다. 반대로 기존 거래를 지우면 실패가 사라져 같은 결함과 열등 전략을 다시 시험하게 된다.

## 결정

1. 전체 유격 연구후보는 기존 funnel의 최대 25개를 유지한다. 이 단계는 탐색이며 승자 선정이 아니다.
2. `backend/app/research/survivor_watchlist.py`는 통과 증거가 있는 후보만 최대 10개 감시목록으로 결정적으로 선택한다.
3. 독립 시장기회, BASE, STRESS는 각각 30건 이상이어야 한다. 30건 미만 후보로 빈 자리를 채우지 않는다.
4. BASE·STRESS 승률 70% 이상과 비용 후 양의 기대값을 모두 요구한다. BASE Profit Factor는 1.05 이상, STRESS는 1보다
   크고 bootstrap 하한도 양수여야 한다.
5. DSR, PBO, 시간순 OOS, 인접 파라미터 강건성, drawdown, 종목·레짐 집중도, 비용 모델과 no-lookahead를 모두 통과해야
   한다.
6. 같은 `hypothesis_id` 및 `parameter_fingerprint`는 표시 이름이 달라도 하나의 후보로 간주한다. 사전등록한 실제 파라미터
   변형은 별도 후보로 두되 다중시험 수에 포함한다.
7. 10개가 찬 후보는 표시 승률만 높은 정도로는 교체하지 못한다. 최약 기존 후보보다 BASE·STRESS 중 더 나쁜 승률이 높고, 승률
   신뢰구간 하한·기대값·Profit Factor·bootstrap 하한이 모두 열화되지 않을 때만 교체한다.
8. 탈락 후보는 거래와 판단 근거를 삭제하지 않는다. `RETIRED/OFF` 또는 미등록 상태로 보존하여 재시험과 회귀를 막는다.
9. 감시목록 편입은 즉시 전략 승격이 아니다. 모든 후보는 `FORWARD_LIVE_PUBLIC_MONITORING_REQUIRED`로 표시하고 현재 버전의 독립 자연표본을
   추가로 누적한다.
10. 감시목록은 PAPER 연구 전용이다. 실제 주문, private API, 인증, API Key, secret, wallet과 입출금 경로는 0으로 유지한다.

## 전략 장기 운영단계

`25개 이하 탐색후보 → 10개 이하 증거 통과 생존 감시목록 → 1개 이하 ACTIVE PAPER 챔피언`을 유지한다. 각 화살은 단순 승률 순위가
아니라 사전등록 증거 관문을 의미한다.

## 검증

- `backend/tests/test_survivor_watchlist.py`는 소표본 채우기 금지, 10개 상한, 중복 제거, 엄격한 증거 우위 교체와 PAPER 안전성을 검증한다.
- `config/regression_contracts.json`은 이 규칙을 누적 회귀계약으로 고정한다.
- 실제 수익성은 이 모듈의 통과로 입증되지 않는다. 동결 Run 리플레이와 현재 버전 자연표본이 추가로 필요하다.
