# ADR-064 실패 런타임의 단일 유지관리 복구

- 상태는 승인이다.
- 날짜는 2026-08-27이다.

## 맥락

기준 서비스의 시장 consumer와 저장이 멈춘 뒤 queue가 4,096건으로 포화됐고 신규 PAPER 진입은
안전하게 잠겼다. 기준 6시간 실패 증거를 모두 보존한 뒤 Wave 61·62 불변 릴리스를 준비했지만,
원장 유지관리기는 정상 런타임만 기준선으로 받아 `ENTRY_LOCKED`와
`QUEUE_LIMIT_EXCEEDED` 때문에 전환 자체를 시작할 수 없었다. 이미 실패한 서비스를 먼저 정상화할
별도 재시작을 하면 same-Run 단일 전환과 닫힌 원장 검증 경계가 깨진다.

## 결정

명시적 `--allow-failed-runtime-recovery`에서만 기존 기준선의 `ENTRY_LOCKED`와
`QUEUE_LIMIT_EXCEEDED`를 허용한다. 두 상태는 이미 신규진입이 차단된 consumer 사고의 결과다.
포지션, 실제 주문, 인증, PAPER 모드, 저장 허용, Run, 오류, critical lag와 나머지 안전조건은 기존
검사를 그대로 통과해야 한다. 허용 밖 위반이 하나라도 있으면 유지관리를 시작하지 않는다.

전환 뒤 새 불변 서비스는 override 없이 원래의 엄격한 안전검사를 통과해야 한다. 증거에는 override
요청·적용 여부, 시작 위반과 고정 사유를 기록한다.

## 결과

실패한 consumer를 정상처럼 취급하지 않으면서도 기존 서비스를 한 번만 종료해 WAL checkpoint,
닫힌 clone, 다른 device 전수검사와 같은 Run 불변 릴리스 복구를 한 경계에서 수행할 수 있다.
이 옵션은 일반 배포나 열린 포지션을 우회하는 기능이 아니다.
