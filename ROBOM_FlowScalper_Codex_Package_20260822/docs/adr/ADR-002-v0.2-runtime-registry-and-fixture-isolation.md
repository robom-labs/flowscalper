# ADR-002. v0.2 READY 런타임, 전략 레지스트리, fixture 격리

- Status: Accepted
- Date: 2026-08-22
- Owners: ROBOM / Codex

## Context

0.1은 시작 즉시 fixture 표본과 완료 거래를 만들고, LIVE 모드는 공개 WebSocket 첫 이벤트를 확인한 뒤 연결을 닫는다. 이 상태는 연구 샘플과 fresh LIVE PAPER 성과를 혼동하게 하고 A/B 전략 모듈이 실제 시장 이벤트에서 실행되지 않게 한다.

## Decision

1. 기본 부팅은 `READY`이며 어떤 거래나 fixture 성과도 생성하지 않는다.
2. 사용자의 `실시간 PAPER 시작` 동작만 fresh `LIVE_SHADOW_PAPER` Run을 만들 수 있다.
3. fixture는 명시적인 `DEMO_FIXTURE` Run과 별도 sample type으로만 저장하고 LIVE 성과에서 제외한다.
4. 지속 supervisor는 공개 REST와 공개 WebSocket만 사용한다. Binance `/public`과 `/market`을 분리하고 Bybit fallback은 새 Run으로만 전환한다.
5. 전략 A/B/C/D는 Registry 메타데이터와 `ACTIVE`, `SHADOW`, `OFF`, LONG·SHORT 설정을 공통 파이프라인에 연결한다.
6. main PAPER 계좌는 최대 한 포지션, 전략별 shadow 계좌는 상호 독립으로 유지한다.
7. 자연 신호를 만들기 위해 문턱을 낮추지 않는다. 실제 저장 이벤트를 리플레이해 계획·체결·종료·원장 경로를 검증한다.

## Official evidence

- Binance 공식 문서는 `/public`, `/market`, `/private` 라우팅 분리, 24시간 연결 수명, 3분 ping, 10분 pong 제한, 연결당 1024 스트림을 명시한다.
- Binance 로컬 호가장 문서는 snapshot 이후 `U/u/pu` 연속성과 gap 발생 시 snapshot 재시작을 요구한다.
- Bybit 공식 문서는 public linear URL, public topic 무인증, 20초 heartbeat 권장, orderbook snapshot/delta reset을 명시한다.
- Lightweight Charts 공식 v5 문서는 `createChart`와 통합 `addSeries` API, React 통합, TypeScript 선언을 제공한다.

## Safety impact

READY와 공개 데이터 검증 잠금으로 LIVE 오표시를 막는다. 실제 주문 모드와 private URL은 추가하지 않는다. fixture 데이터는 실행 모드·Run·sample type·성과 쿼리에서 모두 분리한다.

## Consequences

백엔드는 브라우저 연결과 무관하게 PAPER 포지션을 관리한다. UI는 전체 snapshot 뒤 revision 기반 delta를 병합한다. 공개 이벤트 저장량을 제한하기 위해 bounded queue와 배치 저장을 사용하며 저장 압박 시 신규 진입을 잠근다.

## Validation

Fresh run 0값, fixture 분리, supervisor 재연결·gap·종료, 50/10 유니버스, Registry 모드·방향, shadow 독립성, 저장 리플레이 checksum, 실제 주문 경로 0을 자동 테스트한다.
