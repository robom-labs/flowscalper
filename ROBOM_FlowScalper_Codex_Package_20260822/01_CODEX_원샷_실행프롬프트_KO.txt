## 최종 목표

로그인·아이디·비밀번호·거래소 API Key 없이 실행되는 로컬 프로그램을 만든다.

## 자율작업 원칙

작업 중 막히면 사용자의 계정정보를 요구하며 중단하지 말고 다음 순서로 해결하라.

1. 공식 문서를 다시 확인한다.
2. 가장 안전하고 단순한 설계를 선택한다.
3. 결정과 가정을 ADR에 기록한다.
4. 네트워크 기능이 막혀도 fixture와 synthetic simulator로 나머지 구현·테스트를 계속한다.
5. 1차 공급자가 지역 또는 네트워크 문제로 불가능하면 2차 공개 공급자 어댑터를 사용한다.
6. 기능을 거짓으로 완료처리하지 말고, 실제 연결이 필요한 검사는 `NETWORK_NOT_RUN`으로 정확히 보고한다.
7. 외부 서비스의 현재 API가 문서와 달라졌다면 최신 공식 문서에 맞게 수정하고 `OFFICIAL_REFERENCES.md`와 ADR을 갱신한다.

질문이 없어도 안전한 기본값으로 계속 진행하라. 단, 사용자의 비밀정보나 실제 계정이 없으면 해결할 수 없는 기능은 이번 범위에서 제외하고 명확한 Stub과 이유를 남겨라. 이번 버전은 공개데이터와 내부 페이퍼 체결만으로 완성 가능하므로 계정정보 부족을 작업중단 사유로 삼지 마라.

## 핵심 구현 범위

### 1. 실시간 공개 시장데이터

- Binance USDⓈ-M Futures의 최신 공개 WebSocket endpoint 분리구조와 공식 stream mapping을 따른다.
- 일반 시장데이터와 고빈도 공개 호가데이터가 서로 다른 경로로 분리된 경우 연결을 분리한다.
- 연결 24시간 수명, ping/pong, 재연결, stream 구독한도, sequence gap을 처리한다.
- 심볼·가격단위·수량단위·상태는 공개 REST `exchangeInfo` 또는 동등 endpoint에서 동적으로 읽는다.
- 24시간 거래대금과 실제 스프레드·호가깊이를 기준으로 종목을 선별한다.
- Bybit fallback은 public linear WebSocket snapshot/delta 규칙을 정확히 따른다.
- 시장데이터 공급자를 바꾸면 새 Run을 시작하며 기존 Run과 성과를 섞지 않는다.

### 2. 다종목 자동 Universe

기본적으로 활성 USDT perpetual 중 다음 필터를 통과한 종목을 대상으로 한다.

- 상태가 Trading
- USDT 선형 무기한 계약
- PreLaunch·Settling·Delivering·Closed 제외
- 상장 직후 종목 제외
- 안정적인 bid/ask 존재
- 24시간 거래대금 하한 통과
- 스프레드 상한 통과
- 상위호가 깊이 하한 통과
- 최근 체결이 존재
- 데이터 신선도 통과
- stablecoin 대 stablecoin, 레버리지토큰, 비정상 계약 제외

기본 넓은 감시 50개, 정밀 감시 8~12개로 시작하되 장비와 실제 데이터율을 측정해 자동 축소할 수 있게 한다. BTC·ETH·SOL은 거래가능할 경우 관찰 우선순위에 포함하지만, 유동성·비용 필터를 면제하지 않는다.

### 3. 자체 차트

TradingView를 사용하지 않는다.

- 실제 agg trades로 1초·5초·15초·1분 캔들을 로컬 생성한다.
- Lightweight Charts 또는 동등한 오픈소스 라이브러리로 표시한다.
- 현재 bid/ask, mid, microprice, micro-VWAP, 진입가, 익절가, 손절가, 후보구조, 진입·청산 마커를 표시한다.

### 4. 초기 전략 두 개

A. 유동성 쓸기 → 흡수 → 범위 복귀 반전

- 의미 있는 단기 고점·저점 이탈
- 공격적 체결 급증
- 주문량 대비 가격진행 실패
- 반대편 호가 재충전
- OFI 반전
- microprice 복귀
- 기존 범위 재진입 지속
- 비용·손익비·위험 게이트 통과

B. 변동성 압축 → 돌파 → 눌림 → 재가속

- 단기 변동성 압축
- 주문흐름을 동반한 돌파
- 최초 급등락 추격 금지
- 짧은 눌림 대기
- 반대체결의 가격영향 실패
- 원래 방향 호가 재충전
- OFI·체결불균형·microprice 재정렬
- 비용·손익비·위험 게이트 통과

모든 기준값은 설정파일로 분리하고 고정 숫자 하나에만 의존하지 말고 종목별 rolling percentile·robust z-score를 사용한다.

### 5. 진입 결정

GPT가 판단하지 않는다. 로컬 규칙엔진이 결정한다.

첫 버전은 규칙기반이다. 충분한 실측자료가 쌓이기 전에는 TP확률을 숫자로 꾸며 표시하지 말고 `CALIBRATING`으로 표시한다.

진입 전에 반드시 확정할 값:

- strategy_id
- symbol
- side
- signal_timestamp
- expected_entry
- worst_allowed_entry
- initial_stop
- selected_take_profit
- noise_buffer
- gross_reward
- total_expected_cost
- net_reward
- net_risk
- net_reward_risk
- risk_budget
- quantity
- expected_slippage
- rejection reasons
- edge-decay exit conditions

통과 가능한 익절 후보와 유효한 손절이 모두 없으면 진입하지 않는다.

### 6. 손절

공통 noise buffer:

```text
max(
  2 ticks,
  current_spread × configured_multiplier,
  rolling percentile of micro price noise,
  conservative exit-slippage buffer
)
```

전략 A 롱은 sweep low 아래, 숏은 sweep high 위에 둔다.
전략 B 롱은 pullback low 아래, 숏은 pullback high 위에 둔다.

손절은 최초 위치보다 불리한 방향으로 절대 이동하지 않는다.

### 7. 익절

다음 후보를 만들고 비용 차감 후 보수적 순기대값이 가장 좋은 목표를 선택한다.

- micro-VWAP
- 범위 중앙 또는 반대편 경계
- 다음 실제 유동성 집중가격
- 돌파폭 기반 구조목표
- 수집된 유사신호 MFE의 보수적 분위수

초기에는 통계확률이 없으므로 구조적 손익비와 비용비율을 기준으로 진입한다. 데이터가 충분해진 뒤 시간순 미사용 검증과 확률보정을 통과한 로컬 모델만 Paper 게이트로 추가할 수 있다.

### 8. 고정 120초 청산 금지

120초가 됐다는 이유만으로 청산하지 않는다.

계속 계산할 것:

- structure_health
- flow_health
- liquidity_health
- microprice_alignment
- opposite_aggression
- spread_health
- remaining_edge
- data_freshness

진입근거가 살아 있고 남은 기대값이 양수면 계속 보유한다. 근거가 사라지거나 남은 기대값이 0 이하로 떨어지면 TP·SL 사이에서도 조기청산한다.

시스템 오류 방지용 STALE_POSITION 안전장치는 별도 구현한다. 정상 청산 목표로 사용하지 말고, 데이터가 충분하면 전략·종목·상태별 보유시간 99.5백분위를 사용하며 cold start 절대 비상한도는 15분으로 둔다.

### 9. 1,000 USDT 페이퍼 계좌

기본 프로필:

- initial_equity: 1000 USDT
- risk_per_trade: 0.10% (초기 약 1 USDT)
- max_open_positions: 1
- max_daily_trades: 12
- daily_loss_limit: 5 USDT
- weekly_loss_limit: 15 USDT
- maximum_drawdown_lock: 3%
- averaging_down: false
- martingale: false
- pyramiding: false
- stop_widening: false

동일 신호를 BASE와 STRESS 비용모델에 동시에 그림자 계산해 비교한다. 선택적으로 2배 레버리지 shadow profile을 제공하되, 거래당 허용손실은 1 USDT로 유지한다.

### 10. 실제 호가 기반 가상체결

last trade만 보고 체결처리하지 않는다.

- 신호 후 configurable latency 적용
- 롱 진입은 실제 ask 깊이를 소비
- 숏 진입은 실제 bid 깊이를 소비
- weighted average fill 계산
- 시장성 지정가 IOC처럼 최대 허용가격 밖의 잔량 취소
- 부분체결 지원
- depth가 부족하면 거래 거부
- 청산은 반대호가를 소비
- TP는 실제 청산 가능한 호가가 목표를 통과하고 수량이 있을 때 체결
- SL은 trigger 후 latency와 보수적 slippage를 적용
- TP/SL 선후관계가 불명확하면 보수적으로 손절 우선
- 수수료·스프레드·진입/청산 슬리피지를 모두 계좌에서 차감
